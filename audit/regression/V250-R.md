## تغییرات V250

1. History تنها کنترل‌های سبک را در سازندهٔ فرم می‌سازد؛ پس از رویداد `Shown` خواندن پروژه‌ها از طریق `Task.Run` خارج از Thread رابط کاربری انجام می‌شود. انتخاب Project نیز `GetSummary` را در worker اجرا می‌کند و generation guard مانع نمایش نتیجهٔ انتخاب قدیمی یا فرم بسته می‌شود.
2. فقط ۲۰۰ استقرار در هر صفحه History رندر می‌شود؛ دکمه‌های Previous/Next و شمارندهٔ صفحه و مجموع استقرار اضافه شدند.
3. تب‌های دیگر به‌شکل placeholder ثبت می‌شوند و تنها پس از کلیک کاربر ساخته می‌شوند (Lazy Tab). هنگام اولین انتخاب، **خود TabPage ساخته‌شده** جای placeholder را می‌گیرد؛ این نکته برای حفظ عمر async Loader/Timer و عدم Dispose زودهنگام تب ضروری است. نام تب و mapping بخش Export حفظ می‌شود.
4. Code Quality فقط در زمان انتخاب تب خوانده می‌شود؛ خواندن `DiagnosticStore.Read().ToArray()` در `Task.Run` انجام می‌شود، تمام به‌روزرسانی‌های WinForms پس از بازگشت به UI و با کنترل generation صورت می‌گیرد.
5. در جدول Code Quality، حداکثر ۲۰۰ Issue در هر صفحه ساخته می‌شود و فیلترهای تایپی با debounce ۲۵۰ms انجام می‌شوند. Export JSON/Markdown/Handoff بر اساس Build انتخاب‌شده باقی می‌ماند.
6. Callهای Export/DiagnosticBundle، سرویس‌های استقرار، Backup، فایل‌های JSONL و نگهداشت داده تغییر نکردند؛ فقط زمان خواندن و تعداد ردیف‌های UI تغییر می‌کند.
