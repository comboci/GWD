# V266 — Email notifications
Open File > Settings > Email Notifications. Set SMTP host and STARTTLS port (typically 587), sender, optional distinct login, password/app password and recipient. Select result types and enable notifications, optionally Send Test Email, then Save in this dialog. Cancel does not save. By default automatic sending is disabled.
The whole email configuration is protected with Windows DPAPI CurrentUser in HKCU, not in project profiles or shared settings.json. Do not paste credentials into GitHub or chat. Use a dedicated sending account/app password if supported. No cleartext SMTP fallback, raw logs, exception text or credentials in emails. System.Net.Mail supports STARTTLS, not implicit TLS port 465 or OAuth-only accounts. SMTP acceptance is not proof of inbox delivery.
Desktop DeployAsync sends a best-effort email after the terminal outcome (including Fast Local Test, cancel or failed recovery), before the result dialog; 15-second cancellation budget for SMTP. Failure does not change the deployment result. Closing the program, machine/network outages, SMTP rejection or failures before entering DeployAsync can prevent notification. No background delivery queue, CLI notifications or retry in this release.
Build, Windows UI, actual SMTP and deployment integration NOT_RUN.
