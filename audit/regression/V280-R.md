# V280-R | سریالی‌کردن ثبت تنظیمات و حصار اعتبارنامه

مبنا: 8f9827b3f421690165eba0483ee0892c470f0559 (V279-R).

یک writer مشترک برای تغییرات JSON و رجیستری مشخص شد. تغییر هر فیلد از جدیدترین JSON آغاز می‌شود، خطای خواندن فایل معیوب باعث نوشتن تنظیمات پیش‌فرض روی آن نمی‌شود، و ثبت کامل Snapshot با شناسه قدیمی رد می‌شود. API ثبت کامل نمی‌تواند بایت‌های DPAPI قدیمی را بازنویسی کند. ثبت صریح Remember یک نسل جدید می‌سازد و ثبت اصلاحِ رمز فقط در نسل معتبر مجاز است. محل و قالب اصلی JSON و مسیر Registry حفظ؛ دو فیلد افزایشی‌اند. این مرحله به‌تنهایی صف UI را به writer منتقل نکرده است.

پذیرش مالک (اجرا نشده): حفظ فیلدها در نوشتن متوالی، کنترل خطای فایل معیوب، خواندن کلیدهای رجیستری قدیمی، رفتار mutex در دو نشست مجاز، و عدم بازگشت رمز بعد از فراموشی.

آزمون، کامپایل، Build، Runtime، Deploy و CI اجرا نشد. پذیرش ویندوز بر عهده مالک است.

گام بعد: A03.2: صف background با snapshot ثابت، ترتیب مستقیم و queued، تخلیه هنگام خروج و گزارش خطا.
