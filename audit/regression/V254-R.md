## یک اصلاح مستقل و محدود

1. `RuntimeMetricsService` آخرین نمونهٔ واقعی موفق را در `_latestSample` در همان lock مشترک با History ذخیره می‌کند. متد `GetLatestSample()` فقط همان نمونهٔ immutable را بازمی‌گرداند: **نه `Process.Refresh`، نه زمان جعلی، نه افزایش صف**.
2. نمونه‌برداری `WizardForm` همچنان مالک یگانهٔ همین مسیر UI و با نرخ ۵ ثانیه است؛ هیچ تغییری در `Sample()` یا فرمول CPU انجام نشد. رفتار دیگر مصرف‌کنندگان `GetHistory()` و Export JSON/TXT نیز ثابت است.
3. `DiagnosticsCenterForm` اکنون فقط از `GetLatestSample()` می‌خواند، با timestamp **واقعی `sample.At`** نشان می‌دهد و تنها هنگام تغییر `sample.At` تاریخچهٔ نمایشی را بازمی‌سازد؛ بنابراین Tickهای ۲ثانیه‌ای بدون نمونهٔ جدید رندر ندارند.
4. تایمر مشاهدهٔ Diagnostics Center فقط زمانی کار می‌کند که تب CPU/Memory **انتخاب شده** باشد؛ هنگام تغییر به تب دیگر Stop می‌شود و در بازگشت Start + Refresh فوری (بدون Sample) دارد. LazyTab V250 و وضعیت Export/V251 تغییر نمی‌کنند.
5. تا قبل از اولین Sample واقعی، UI پیام «Waiting for the first CPU/RAM measurement» نمایش می‌دهد و عدد صفر ساختگی به‌عنوان CPU اندازه‌گیری‌شده ادعا نمی‌کند.
6. هنگام Dispose تب، Timer متوقف و ارجاع callback آزاد می‌شود؛ `FormClosed` همچنان تایمر را Dispose می‌کند.

## محدودیت‌ها و پذیرش کاربر

- `GetLatestSample` زمان واقعی آخرین اندازه‌گیری را حفظ می‌کند؛ هنگام معطل‌ماندن UI یا توقف منبع نمونه‌برداری، ممکن است داده کهنه باشد و timestamp این موضوع را آشکار می‌کند. این Commit مانیتور CPU مستقل برای فرم Diagnostics نمی‌سازد.
- سناریوهای تست روی Windows: باز و بسته‌کردن Diagnostics، انتخاب متوالی CPU/History/Code Quality، برگشت به CPU و نمایش تازه‌ترین timestamp، عدم افزایش شمارش History با بازکردن تب، Export تمام تاریخچه، زمان‌بندی ۵ثانیه‌ای، CPU_percent و RAM در بار سنگین، Close/Dispose.
- ارزیابی صرفاً **Static Source Review** است؛ هیچ بهبود عددی CPU/RAM یا تأیید UI عملی ادعا نمی‌شود.
- `AUTOMATED_TESTS=NOT_RUN`؛ `BUILD_VALIDATION=NOT_RUN`؛ `RUNTIME_REVIEW=PENDING_USER`؛ `TESTING_OWNER=USER`.
- `N-UI09b=SOURCE_FIXED / RUNTIME_PENDING`؛ `A03=IN_PROGRESS` و `A04=NOT_STARTED`.
- نوبت بعدی: `N-UI10`، بررسی غیرفعال بودن `Fast IIS Update` و safetyِ fingerprint / rollback قبل از هر تغییر.
