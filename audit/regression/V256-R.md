## Root cause

در بلوک غیرفعال Fast IIS Update (`if(false && ...)`)، `ReadSmartState` می‌توانست صرفاً به Snapshot ذخیره‌شدهٔ Repository یا Legacy Hosted تکیه کند و هنگام یکسان بودن Backend/Migration Hash، شاخهٔ `Hosted baseline copy` را اجرا کند. **هویت واقعی مسیر فعال IIS، AppPool، Snapshot داخل Hosted Folder، Release-ID از HTTP و SHA256 فایل‌های مستقرشده قبل از کپی الزاماً بررسی نمی‌شدند.** وضعیت موفق یک Build، به‌تنهایی اثبات سلامت نسخهٔ سرویس‌دهنده نیست.

## اصلاح محدود F1

1. متد خواندنی `RequireHostedBaselineProvenanceAsync` به `DeploymentService` اضافه شد و **داخل همان شاخهٔ Fast IIS که اکنون غیرفعال است**، پیش از هر مقایسهٔ Fingerprint برای تصمیم reuse فراخوانی می‌شود.
2. Fail-Closed: فقط `Fast IIS Update + Local Server + Single Folder` با `_iisAttempt` فعال/قفل‌شده و **قبل از mutation** واجد بررسی است؛ Versioned/Remote/بدون قفل مجاز نیستند.
3. مسیر Hosted با `RequireExclusiveLocalTarget` و `RequirePlainTree` بررسی می‌شود؛ `.deployment-incomplete` با `File.GetAttributes` (نه `File.Exists` که ممکن است access denied را پنهان کند) رد می‌شود.
4. فقط فرمان‌های **read-only** واقعی IIS از `IisSafety` استفاده می‌شود: صحت Started بودن Site/Pool، تطابق دقیق PhysicalPath با HostingRoot، ApplicationPool برنامهٔ Root و انحصاری بودن Pool برای همان سایت.
5. فایل `.smart-deploy-state.json` مستقرشده باید به‌طور کامل با `SmartDeployState` Repository مساوی باشد؛ Manifest و Frontend Marker باید `releaseId` یکسان و معتبر، `sourceVersion` معلوم/سازگار، قرارداد `uiVersionVerified=true`، `frontendSha256` معتبر و یکسان با `FrontendOutputHash` داشته باشند. `HashDirectory(wwwroot)` با مقدار اعلام‌شده مقایسه می‌شود.
6. علاوه بر بررسی دیسک، از `VerifyRunningFrontendReleaseAsync` برای مقایسهٔ `releaseId` واقعی HTTP و hash استفاده می‌شود. API تنها با حالت `Strict` و پاس‌کردن `VerifyRunningApiReleaseAsync` قبول می‌شود تا Compatible/UNVERIFIED به‌عنوان Release Provenance معتبر شناخته نشود. شواهد ناقص باعث **IOException قبل از CopyDirectory** می‌شوند.
7. چهار `if(false &&)` همچنان **بدون تغییر** باقی مانده‌اند؛ هیچ فعال‌سازی Fast Skip، تغییر Build، File Copy، IIS، SQL، Backup، Rollback، marker cleanup یا استقرار واقعی صورت نگرفت.

## مرزهای امنیتی که هنوز اثبات نشده‌اند

- F1 فقط یک **gate آماده‌شده در بلوک غیرقابل‌دسترسی فعلی** است؛ هیچ افزایش سرعت واقعی یا محدودسازی مسیر فعال Fast IIS در Runtime ایجاد نمی‌کند.
- رابطهٔ رمزنگاری‌شدهٔ مستقل بین API binary و Release-ID هنوز وجود ندارد؛ `Strict API version` معادل hash باینری نیست (F2).
- `HashDirectory`/IIS read-only observations یک Snapshot اتمیک از تمام فایل‌های میزبان ایجاد نمی‌کند؛ تغییر فایل بین Verification و `CopyDirectory` (TOCTOU) و manifest/staging تازه باید در F4/F2 بسته شود.
- DB migrations/initializer و فایل‌های config و وابستگی خارج از فهرست fingerprint باید در F3 ممیزی شوند.
- احتمال دگرگونی کنترل IIS، اشتراک‌گذاری pool، recovery owner و failure injection باید توسط مالک در محیط ایزوله سنجیده شود. **چهار شرط Fast Skip نباید با این Commit فعال شوند.**
